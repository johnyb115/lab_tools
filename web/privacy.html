🔒 Privacy & Security

How Lab Tools handles your data, and what you should know about using it.

Your files stay in your browser

Every tool on this site runs entirely as client-side JavaScript. When you upload a CSV, image, PDF, or any other file, it is read into your browser's memory, processed there, and never transmitted to any server. There is no backend — the site is a collection of static files served by GitHub Pages.

  • No file content is uploaded, stored, or logged anywhere.
  • No analytics, telemetry, or tracking scripts are included.
  • No cookies or local storage are used.
  • Downloads are generated in-browser via URL.createObjectURL() on locally computed blobs.

The one exception: Background Remover

The Background Remover tool downloads an AI model from an external server on first use. The model weights (roughly 30–90 MB depending on quality) are fetched from staticimgly.com, a CDN operated by IMG.LY, the maintainers of the @imgly/background-removal open-source library.

Your images are not sent to that server — the model runs locally in WebAssembly inside your browser. However, the download request does reveal your IP address and the fact that you are using the tool. After the first download, your browser caches the model files, so subsequent visits do not repeat the request.

How the site is hosted

Lab Tools is hosted on GitHub Pages, which serves only static files. There is no server-side code, no database, no API, and no way for the site to receive or store anything you type or upload.

The source code is public at github.com/johnyb115/lab_tools — you can inspect every line.

HTTPS

The site is served over HTTPS via GitHub Pages, which means all traffic between your browser and the server is encrypted. This prevents third parties on your network from seeing or tampering with the pages you load.

What about "getting hacked"?

A static site has a very small attack surface compared to a typical web application. There is no login system, no database to breach, no API to exploit, and no stored user data to steal. The main risks are:

  • GitHub account compromise — if the repository owner's GitHub account is compromised, an attacker could push malicious code. This is mitigated by using a strong password and two-factor authentication.
  • Supply-chain attack — a compromised npm dependency could inject malicious code at build time. This is mitigated by keeping dependencies up to date, reviewing npm audit output, and pinning dependency versions.
  • Cross-site scripting (XSS) — all user-controlled strings (file names, column headers, cell values) are escaped before being inserted into the page, preventing injection of malicious scripts.

Recommendations for users

  • Use a modern, up-to-date browser (Chrome, Firefox, Edge, Safari).
  • If you are on a shared or public computer, close the tab when you are done — your data lives in browser memory and is released when the tab closes.
  • If you work with sensitive data, you can verify the site's behavior using your browser's Developer Tools (Network tab) — you will see zero outbound requests when using any tool except the Background Remover's initial model download.
